# AGENTS.md — AI Sabotage Marketing Site

Operational guide for AI agents working in this repo. Read this first.

## What this is

Static marketing/ASO website for **AI Sabotage: Cyber Cards** — a cyberpunk
strategy card game (source app: `/Users/dani/Desktop/repos/ai_sabotage`).
The site's job is to drive app installs: it mirrors the app's ASO keywords,
looks like the game's HUD, and routes visitors straight to the stores.

- Live: <https://erperejildo.github.io/ai-sabotate-web/>
- Repo: <https://github.com/erperejildo/ai-sabotate-web>
- Languages: **English (`/en/`)** and **Spanish (`/es/`)**, Castilian only.
- Hosting: **GitHub Pages**, served from the `/ai-sabotate-web/` subpath
  (so **all internal links must stay relative**).

## Tech stack & key decisions

- **Vanilla HTML/CSS/JS. No framework, no bundler.** Chosen for instant
  loads, trivial deploy, and perfect SEO/ASO. Do not introduce Vue/React/etc.
- **Pages are generated** by `build-pages.js` — never hand-edit `en/*.html`
  or `es/*.html`; they are build output (but they ARE committed).
- **i18n at runtime** via `assets/js/i18n.js` dictionaries applied on DOM
  ready by `assets/js/main.js` (`data-i18n`, `data-i18n-html`,
  `data-i18n-attr`). Generated HTML contains empty/`Auto` placeholders.
- **CI/CD**: GitHub Actions (`.github/workflows/deploy.yml`), not GitLab
  (an early `.gitlab-ci.yml` was deleted because it deployed a competing
  `gh-pages` branch).
- **Prettier is the linter.** `npm run lint` === `npm run format:check`.
- Tests are Playwright (Chromium only), run against a local static server.

## The build generator: `build-pages.js`

Single source of truth for every HTML page. **After ANY edit to it, run
`node build-pages.js`** and commit the regenerated `en/`/`es/` files.

Structure:

- `SITE_BASE = "https://erperejildo.github.io/ai-sabotate-web"` — drives
  `canonical`, `hreflang`, `og:url`. **Update this if a custom domain is added.**
- `PAGES` array — `{ slug, titleKey, build }` for
  `index, rig, cards, friends, ranking, play`.
- Helpers: `head()` (meta/OG/Twitter/fonts preload/CSS links),
  `nav(slug, lang)` (brand `[ AI SABOTAGE ]` + links + ES/EN switcher),
  `footer()` (year + link list), `scripts()` (config → i18n → main, all `defer`).
- Page builders: `buildHome`, `buildRig`, `buildCards`, `buildFriends`,
  `buildRanking`, `buildPlay`.
- The emit loop writes `en/<slug>.html`, `es/<slug>.html`
  (`index` → `index.html`) and finally the root redirect page.

Page `title` comes from `data-title-key` on `<html>` + `dict.titleTemplate`
(`"%title% · AI Sabotage"`). Meta description/keywords/OG are injected from
`meta.*` i18n keys the same way.

## Runtime JS (`assets/js/main.js`)

In order:

1. Reads `window.AI_SABOTAGE_CONFIG` (store URLs) and `window.I18N`.
2. `detectLang()` — `localStorage.lang` → current URL directory (`/en`|`/es`)
   → `navigator.language`. Exposed at the end as `window.__SITE_LANG__`
   (tests rely on this).
3. `render()` — fills `[data-i18n]` (textContent), `[data-i18n-html]`
   (innerHTML), `[data-i18n-attr]` (`attr:key` pairs joined by `;`), sets
   `<title>`, and replaces `%year%` in `footer.copy`.
4. Language switcher `[data-lang-switch]` — preserves the current page via
   regex `/\/(en|es)(\/[^/]*)?$/` and writes `localStorage.lang`.
5. **`DECK` array (20 entries)** + renderer: each entry is
   `{ group, img, cat, name:{en,es}, tag, desc:{en,es} }`;
   `group` ∈ `components|threats|defenses|protocols`, `cat` ∈
   `hardware|dataset|neural|algorithm|quantum|threat|defense|protocol`,
   `tag` is an i18n key in `cardsPage`. Renderer fills every
   `[data-deck]` grid with `DECK.filter(c => c.group === group)`.
   Card images live in `assets/img/` as **`.png`**.
6. Smooth-scroll for in-page anchors (64 px header offset).
7. IntersectionObserver reveal for `.section`, `.hero-art`, `.deck-card`,
   `.step`, `.combo`, etc.
8. **Download button**: `[data-store]` click → `e.preventDefault()` →
   `window.open(isIOS() ? APP_STORE_URL : PLAY_STORE_URL, "_blank", "noopener")`.
   `isIOS()` = `/iPad|iPhone|iPod/` UA test **or**
   `navigator.platform === "MacIntel" && navigator.maxTouchPoints > 1`
   (iPadOS). There is only ONE download button per location; the platform is
   picked automatically. The old "Pick your platform" modal is gone.

## i18n (`assets/js/i18n.js`)

`window.I18N = { en: {...}, es: {...} }`. Top-level key groups (same in both
languages): `siteTitle`, `titleTemplate`, `meta`, `nav`, `footer`, `hero`,
`extra`, `rig`, `cardsPage`, `friends`, `ranking`, `play`.

Rules:

- **Castilian Spanish only** — no Argentine voseo (SABOTEA, Elige, Arma,
  Juega, puedes…). A test enforces a 24-word banned list.
- **No biology terms** anywhere (`biology`, `gene`, `dna`, `protein` are
  test-banned substrings — so never write "genera"/"generates").
- Banned marketing words (tests check all pages): `paywall`, `no ads`,
  `leaderboard`, `sin anuncios`.
- `cardsPage.groupProtocols*` keys and the `protocols` deck group STAY
  (protocols are a card category). The standalone `/protocols` page was
  removed and is 404 — do not resurrect it.
- After editing: **always run `node --check assets/js/i18n.js`**. A dropped
  key (e.g. `cardsDeep:`) caused a SyntaxError that silently broke ALL i18n
  rendering once.

`#2A2A3A`, text `#E8F0FF`, dim `#D8E1EE` (brightened for contrast),

Spacing 4/8/16/24/40. Fonts: **Orbitron** (display/HUD headings),
**JetBrains Mono** (body/data). Motifs: angled corner-cut frames (`clip-path`
on `.btn-primary`), `[ ]` bracket labels, dashed separators, faint grid +
scanlines layers (`.grid-bg`, `.scanlines`), glow text-shadows.

Buttons: `.btn-primary` is the standard CTA everywhere (never `.btn-ghost`
for downloads). `.btn-lg` adds a two-line layout (label + `.btn-sub`).

## Tests (`tests/site.spec.ts`, 37 tests)

Coverage worth knowing before you change markup or copy:

- Every `lang/slug` page loads directly (no 404s) and nav links resolve.
- Root redirects to `/en/`; language switcher preserves slug.
- Cards page: 4 `[data-deck]` blocks × 5 cards = 20; every card `<img>`

  `btn-primary`, opens `play.google.com` by default; an iPhone-UA context

## CI/CD & deployment

`.github/workflows/deploy.yml` triggers on push to `main`/`master` (and
manual dispatch). Jobs:

1. **build**: checkout → cancel competing `pages-build-deployment` runs →
   Node LTS + npm cache → `npm ci` → install Chromium → `format:check` →
   `npm test` → `npm run stage` → validate `dist/` artifacts →
   `configure-pages` → tar artifact → `upload-artifact`.
2. **deploy**: `github-pages` environment → up to **3 attempts** of
   `actions/deploy-pages@v5` (cancelling competing runs between retries) →
   live smoke test of `/`, `/en/`, `/es/`, `/en/ranking.html`.

**Hard-won repo settings** (if deploy fails with "not allowed to deploy"):

- Default branch must be `main`.
- `github-pages` environment must have a branch policy allowing `main`
  (a stale policy for `feature/i18n-pages` broke the first deploy):

```bash
gh api -X PATCH repos/erperejildo/ai-sabotate-web -f default_branch=main
gh api -X POST repos/erperejildo/ai-sabotate-web/environments/github-pages/deployment-branch-policies \
  -f name=main -f type=branch
```

- Settings → Pages → Source must be **GitHub Actions** (not "Deploy from a
  branch"), otherwise the built-in workflow competes and publishes raw source.
- Known harmless warning: `actions/upload-artifact@v4` targets deprecated
  Node 20.
- GitGuardian runs on PRs only.

## Git workflow

- Work on a feature branch → PR via `gh pr create` → squash-merge to `main`
  (merge triggers deploy). `main` stays releasable; CI gates every PR.
- Merged history: #1 i18n+pages, #2 Castilian+footer year, #3 deploy
  workflow+header/brand, #4 cards blocks+button parity, #5 card art → PNG,
  #6 single download button+friends page−protocols page, #7 mobile nav wrap.

## Gotchas / lessons learned

- `en/`+`es/` HTML are **generated**; only `build-pages.js` is editable.
- `.nav-inner` and `.wrap` share an element — any `padding` set on
  `.nav-inner` overrides `.wrap`'s horizontal padding (the mobile header bug,
  fixed by writing `padding: var(--space-md) var(--space-lg)`).
- Mobile nav must **wrap** (`flex-wrap: wrap`), never `overflow-x: auto`
  (users asked for content to push down, not a scrollable strip).
- The site serves from a **subpath**: keep hrefs relative (`rig.html`,
  `./`, `../assets/...`). The only absolute URL is `SITE_BASE` in the head
  tags.
- i18n strings are injected client-side, so `curl`-ing rendered HTML won't
  show them — verify copy in a browser/test, not via raw HTML grep.
- `assets/img/` intentionally has no `.jpeg` card art (a short-lived
  `cards-quality` experiment was reverted; PNGs from the app's `card_imgs/`
  are canonical). `purge_cards.png`/`ui_card_back.png` are NOT used.
- Prettier formats Markdown too — run `npm run format` before committing.
